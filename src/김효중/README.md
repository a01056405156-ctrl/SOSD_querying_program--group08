# SOSD 검색 프로그램 — GitHub 팀원 공유용

Visual Studio 2022에서 **명령 인수나 `DatasetConfig.h` 설정 없이** SOSD 데이터셋의 전체 경로를 콘솔에 입력하고, 정수 키의 위치 및 검색 소요시간을 측정하는 C++17 프로젝트입니다. 화면 안내는 한국어이며 시간은 **나노초(ns)**로 출력합니다.

## 1. 프로젝트 파일

```text
SOSD_GitHub_경로입력_나노초/
├── SOSD_Search.sln                # Visual Studio에서 여는 파일
├── SOSD_Search.vcxproj            # C++ 프로젝트 빌드 설정
├── SOSD_Search.vcxproj.filters    # 솔루션 탐색기 폴더 구분
├── src/
│   └── main.cpp                  # 검색 프로그램 전체 코드
├── README.md                      # 이 사용설명서
└── .gitignore                     # 임시 파일 및 데이터셋 업로드 방지
```

**주의:** Visual Studio에서 새 콘솔 앱을 만들거나 `.cpp` 파일을 따로 추가할 필요가 없습니다. `.sln`을 열면 됩니다. `.vcxproj.user`, `.vs/`, `x64/` 등은 GitHub에 올리지 않습니다.

## 2. 팀원별 준비

1. GitHub 저장소에서 **Code → Download ZIP**으로 전체 프로젝트를 다운로드하거나 `git clone`합니다.
2. 압축을 풀었다면 `SOSD_Search.sln`과 `SOSD_Search.vcxproj`, `src/main.cpp`의 폴더 관계가 위 구조와 같은지 확인합니다.
3. 각자 PC에 SOSD 바이너리 파일을 준비합니다: `uniform_dense_200M_uint32`, `uniform_sparse_200M_uint32` (각 약 800MB, 헤더 포함).
4. Visual Studio 2022에서 `SOSD_Search.sln`을 열고 **Release / x64**를 선택합니다. C++ 데스크톱 개발 워크로드(v143 도구 집합 포함)가 설치되어 있어야 합니다.
5. **빌드 → 솔루션 다시 빌드**, 이어서 **Ctrl + F5**로 실행합니다.
6. **명령 인수는 비워 둡니다.** 실행한 콘솔에서 데이터셋 전체 경로를 입력합니다.

## 3. 데이터셋 파일 경로 입력

예를 들어 콘솔이 `데이터셋 경로 >`라고 물으면 아래처럼 전체 경로를 입력합니다.

```text
C:\SOSD_Data\uniform_dense_200M_uint32
```

또는

```text
C:\SOSD_Data\uniform_sparse_200M_uint32
```

각 팀원은 자신의 데이터셋 위치에 맞춰 다른 경로를 입력해도 됩니다. 한글이 있는 경로도 UTF-8 경로 변환을 통해 처리하도록 구현했습니다. 파일 탐색기의 **경로로 복사** 기능으로 가져온 큰따옴표 포함 경로도 사용할 수 있습니다. 프로그램은 파일 이름에 `uniform_dense`/`uniform_sparse`가 있으면 유형을 자동 판별하고, 둘 다 없다면 유형을 물어봅니다. 데이터셋은 SOSD 바이너리 규격(8바이트 개수 헤더 + 정렬된 uint32 값)에 맞아야 합니다.

## 4. 키 검색 및 시간 측정

메뉴에서 **1. 정수 키 입력 후 위치 검색**을 선택합니다. `0`~`4294967295` 범위의 정수 키를 입력하면 **첫 등장 위치**를 0부터 시작하는 배열 인덱스와 1부터 시작하는 순서로 표시합니다. 없는 키는 없다고 표시합니다. `q`를 입력하면 검색 메뉴를 종료합니다.

표시되는 값의 뜻:

| 항목 | 의미 |
|---|---|
| 인덱스 빌드 시간(ns) | 검색 보조 인덱스 생성에 소요된 시간 |
| 이번 키 검색 시간(ns) | 입력한 키 **한 건** 검색에 소요된 시간 |
| 빌드 + 이번 키 검색(ns) | 그 한 건에 대한 빌드 비용 + 검색 시간 |
| 누적 N회 검색 시간(ns) | 현재 검색 세션에서 입력한 키 N건의 검색 시간 합계 |
| 빌드 + 누적 검색 시간(ns) | 인덱스를 한 번 만든 뒤 N건을 검색한 누적 총시간 |

단위: **1ns = 10⁻⁹초, 1ms = 1,000,000ns**. 나노초로 표시하더라도 측정 정밀도가 1ns임을 보장하지는 않습니다. 매우 빠른 단일 검색은 OS 스케줄링, 캐시, 페이지 폴트, 타이머 해상도의 영향을 많이 받습니다.

## 5. 자료구조 및 성능 비교

- **Dense:** 공식 `uniform_dense_200M_uint32`는 42부터 연속된 2억 정수이므로 값을 이용한 직접 위치 계산을 자동 적용합니다. 파일명의 Dense 구분과 개수/양 끝값을 확인합니다. 원본 전체 값을 검증하는 것은 아닙니다.
- **Sparse:** 값이 불규칙하게 분포하는 정렬 배열을 대상으로 **샘플 인덱스(간격 4096) + 보간 예측 + 지수 탐색 + 이진 탐색** 하이브리드 방식을 자동 적용합니다. 이 방식이 앞선 사용자 실험에서 빠르게 측정되었지만 모든 환경에서 최적을 보장하지는 않습니다.
- 메뉴 **2. 자료구조별 검색 속도 자동 비교**는 존재하는 키 10만 건과 존재하지 않는 키 10만 건을 바탕으로 빌드(ns) + 존재 키 검색(ns) + 부재 키 검색(ns)의 합계를 비교합니다. 사용자에게 자료구조를 직접 고르게 하지 않습니다.
- 벤치마크 합계는 데이터셋 파일을 여는 시간, 쿼리 생성, 결과 검증 시간은 포함하지 않습니다.

## 6. 메모리 제약 관련 주의

원본 파일은 약 800MB이므로 프로그램은 파일 전체를 `vector`로 복사하지 않고 **읽기 전용 메모리 매핑**을 사용합니다. Windows Job Object 설정은 **private committed memory 512MiB**를 제한하지만, 매핑 파일의 전체 물리 메모리 사용량이 512MB 이하임을 증명하지는 않습니다. **수업의 512MB 제한과 동일한 측정 방식으로 별도 검증이 필요합니다.** 또한 Windows 파일 캐시/OS 상태에 따라 측정 시간이 달라질 수 있습니다. 단일 스레드 구현입니다.

## 7. GitHub 업로드 권장 방식

- GitHub Desktop에서 본인 `feature/...` 브랜치를 만들고 작업합니다. 팀 규칙상 `main`에 직접 commit/push하지 않습니다.
- 프로젝트 폴더의 `.sln`, `.vcxproj`, `.vcxproj.filters`, `src/main.cpp`, `README.md`, `.gitignore`를 **상대 경로를 유지한 채** 커밋합니다.
- `.vs`, `x64`, `.vcxproj.user`, `.exe`, 원본 SOSD 데이터셋은 커밋하지 않습니다.
- 커밋 메시지 예: `feat: SOSD 경로 입력 및 나노초 검색 프로그램`
- `Push origin` 후 Pull Request를 생성하여 팀원의 검토를 받고 병합합니다.

## 8. 흔한 오류

- **C1083: main.cpp를 열 수 없음:** `src/main.cpp`가 솔루션 파일과 같은 최상위 폴더 아래에 있는지 확인합니다. ZIP에서 파일만 꺼내 평평하게 배치하면 경로가 깨집니다.
- **데이터셋을 열 수 없음:** 전체 파일 경로와 파일명 확인. `uniform_dense_200M_uint32`는 확장자 없이 저장됩니다.
- **C++ 도구 집합 없음:** Visual Studio Installer에서 C++ 데스크톱 개발 구성요소 설치.
- **한글 깨짐:** Windows 터미널에서 UTF-8 지원 글꼴/인코딩을 확인합니다. Visual Studio 빌드는 `/utf-8` 옵션으로 설정했습니다.
- **시간이 들쭉날쭉함:** `Release / x64`에서 동일 쿼리로 반복 측정하고 중앙값 등을 사용해 비교합니다.

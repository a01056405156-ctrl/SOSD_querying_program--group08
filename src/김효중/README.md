# SOSD uint32 검색 프로그램 — 팀원용 사용설명서

## 1. 프로젝트 개요

SOSD의 **Uniform Dense (uint32)** 와 **Uniform Sparse (uint32)** 데이터셋(각 2억 개 키)을 대상으로, 사용자가 입력한 0~4,294,967,295 사이의 정수 키가 몇 번째에 위치하는지 검색하는 **C++17 콘솔 프로그램**입니다. 검색에 사용한 인덱스의 **빌드 시간 + 키 검색 시간**을 밀리초(ms)로 출력합니다. 존재하지 않는 키는 '데이터셋에 없는 값입니다'라고 알려줍니다.

- Dense: 연속된 정수의 특성을 이용하는 **직접 위치 계산** (O(1)).
- Sparse: **샘플 인덱스 + 보간/지수 탐색 하이브리드** (샘플 간격 4096).
- 사용자가 **자료구조를 고르지 않아도**, 데이터셋에 따라 정해진 방식을 자동 적용합니다.
- 메뉴와 입력 안내는 한국어로 표시됩니다.
- '자료구조 검색 속도 자동 비교' 메뉴에서는 이진 탐색, 샘플 인덱스, 하이브리드 등을 벤치마크합니다. 사용자가 자료구조를 직접 선택하는 메뉴는 아닙니다.

> **주의:** Sparse의 하이브리드는 이전 실험에서 유리했던 방식으로 고정돼 있습니다. 모든 환경에서 전역 최적임을 보장하지 않습니다. 최적 방식은 쿼리와 PC 환경에 따라 바뀔 수 있습니다.

## 2. 저장소에 올릴 파일과 구조

```text
SOSD_Search/
├── SOSD_Search.sln              ← 팀원은 이 파일로 Visual Studio에서 프로젝트를 엽니다.
├── SOSD_Search.vcxproj          ← C++ 프로젝트 빌드 설정
├── SOSD_Search.vcxproj.filters  ← 솔루션 탐색기 소스/헤더 분류
├── src/
│   ├── main.cpp                ← 검색 프로그램
│   └── DatasetConfig.h         ← 각 컴퓨터의 데이터셋 파일 경로 설정
├── .gitignore                  ← 빌드 산출물 및 로컬 설정 제외
└── README.md                   ← 이 사용설명서
```

**반드시 `.sln`, `.vcxproj`, `.vcxproj.filters`, `src/main.cpp`, `src/DatasetConfig.h`를 함께 올리세요.** 코드 파일 두 개만 올리면 팀원이 새 프로젝트를 만들어야 합니다. 소스 파일은 `src/` 아래에 그대로 둬야 빌드 경로가 맞습니다.

## 3. 팀원이 GitHub에서 받는 방법

1. GitHub 저장소에서 **Code → Download ZIP** 또는 `git clone`으로 프로젝트 전체를 내려받습니다.
2. ZIP이라면 압축을 풉니다. `SOSD_Search.sln`과 `SOSD_Search.vcxproj`가 같은 폴더에 있는지 확인합니다.
3. **`SOSD_Search.sln`을 더블클릭**해 Visual Studio 2022에서 엽니다. **새 콘솔 앱을 만들 필요가 없습니다.**
4. Visual Studio에 **Desktop development with C++ (C++를 사용한 데스크톱 개발)** 워크로드와 MSVC v143 도구가 설치되어 있어야 합니다.

## 4. SOSD 데이터셋 준비 및 연결 (필수)

**GitHub 공유 ZIP에는 원본 데이터셋이 없습니다.** 각 팀원은 다음 두 SOSD 바이너리 파일을 직접 준비해야 합니다.

- `uniform_dense_200M_uint32`
- `uniform_sparse_200M_uint32`

권장 폴더 구조:

```text
C:\SOSD_Data\
    uniform_dense_200M_uint32
    uniform_sparse_200M_uint32
```

파일은 일반적으로 각각 **800,000,008바이트**(약 763MiB)입니다. `uint32` 데이터는 8바이트 개수 헤더와 2억 개의 4바이트 정수로 구성됩니다. `data` 폴더에 파일이 없다면 [SOSD 공식 저장소](https://github.com/learnedsystems/SOSD)의 데이터 생성 안내를 참고하세요.

### Visual Studio에서 데이터셋 연결

1. Visual Studio 오른쪽 **솔루션 탐색기**에서 **헤더 파일 → `DatasetConfig.h`**를 더블클릭합니다.
2. 기본 경로는 다음과 같습니다.

```cpp
namespace SosdConfig {
inline constexpr const char* DENSE_PATH  = "C:/SOSD_Data/uniform_dense_200M_uint32";
inline constexpr const char* SPARSE_PATH = "C:/SOSD_Data/uniform_sparse_200M_uint32";
}
```

3. 두 파일을 `C:\SOSD_Data`에 넣었다면 **수정할 필요가 없습니다.**
4. 다른 곳에 파일이 있다면 **그 PC의 실제 전체 파일 경로**로 수정하고 저장합니다. 예를 들면:

```cpp
inline constexpr const char* DENSE_PATH  = "D:/SOSD/data/uniform_dense_200M_uint32";
inline constexpr const char* SPARSE_PATH = "D:/SOSD/data/uniform_sparse_200M_uint32";
```

5. **빌드 → 솔루션 다시 빌드**로 경로 변경을 반영합니다.

> 경로는 **폴더가 아닌 데이터셋 파일명까지** 적어야 합니다. C++ 문자열에서 `\` 대신 `/`를 쓰면 간편합니다. 개인 컴퓨터에서만 변경한 경로는 공동 저장소에 그대로 커밋하지 않는 것이 좋습니다.

## 5. 빌드와 실행

1. Visual Studio 상단에서 구성 **Release**, 플랫폼 **x64**를 선택합니다.
2. **빌드 → 솔루션 다시 빌드**를 클릭합니다.
3. **Ctrl + F5** (디버깅하지 않고 시작)를 누릅니다.
4. **명령 인수는 입력하지 않습니다.** `main.cpp`를 프로젝트에 다시 추가할 필요도 없습니다.
5. 화면의 한국어 안내에 따라 데이터셋(1 = Dense, 2 = Sparse) → 작업(1 = 정수 키 검색, 2 = 검색 성능 자동 비교)을 선택합니다.
6. 키 검색을 선택했다면 정수 키를 입력하고 Enter를 누릅니다. `q`를 입력하면 이전 메뉴로 돌아갑니다.

### 출력 예시 (시간은 실제 환경에서 달라집니다)

```text
[데이터셋 선택]
 1. Uniform Dense (uint32)
 2. Uniform Sparse (uint32)
 q. 프로그램 종료
번호 입력 > 1

[작업 선택]
 1. 정수 키 입력 후 위치 검색
 2. 자료구조 검색 속도 자동 비교
 0. 다른 데이터셋 선택
번호 입력 > 1

검색할 정수 키 > 100
[검색 결과]
입력한 정수 키: 100
결과: 찾았습니다!
데이터셋의 위치 (1부터): 59번째
배열 인덱스 (0부터): 58
인덱스 빌드 시간: ... ms
이번 키 검색 시간: ... ms
빌드 + 이번 키 검색: ... ms
```

- **빌드 시간**: 별도 검색 인덱스를 생성하는 시간(원본 파일 개방·매핑 시간은 제외).
- **검색 시간**: 해당 키의 위치를 확인하는 데 걸린 시간.
- **빌드 + 이번 키 검색**: 단일 검색 기준 총시간. 매우 짧은 시간은 측정 오차가 클 수 있습니다.
- **누적 합계**: 한 번 빌드하고 여러 키를 검색했을 때의 측정 결과.
- **성능 비교 메뉴**: 존재/부재 키 쿼리 각각 10만 개를 사용해 각 방식의 빌드·검색 시간을 비교합니다. 쿼리 생성/파일 개방 시간은 제외합니다.

## 6. 자주 생기는 문제

| 증상 | 확인 방법 |
| --- | --- |
| 데이터셋 파일을 열 수 없다고 나옴 | `src/DatasetConfig.h`의 경로가 실제 파일명까지 정확한지 확인 |
| `main.cpp` 또는 헤더를 못 찾음 | ZIP의 폴더 구조를 그대로 유지했는지 확인 |
| Visual Studio에서 빌드 실패 | C++ 데스크톱 개발 워크로드, x64 및 MSVC v143 설치 확인 |
| 측정이 느림 | **Debug가 아니라 Release / x64**인지 확인 |
| 한국어가 깨짐 | Windows 콘솔 UTF-8 지원과 글꼴 확인 |
| 한 컴퓨터에서만 작동 | 데이터셋 바이너리는 GitHub에 포함되지 않음. 그 컴퓨터에도 준비하고 경로 설정 필요 |

## 7. 과제 제출 전 유의사항

- SOSD 데이터셋의 원본 바이너리는 크기가 커서 **GitHub에 업로드하지 않는 것을 권장**합니다. 코드/설명서만 공유하세요.
- 현재 구현은 **메모리 매핑된 파일 + 작은 샘플 인덱스**를 사용하고, Windows Job Object의 512MiB **private commit** 제한을 시도합니다. 이것은 메모리 매핑 페이지까지 포함하는 **실제 물리 메모리 512MB 상한 보장을 뜻하지 않습니다.** 교수님이 정한 메모리 측정 기준에서 반드시 확인해야 합니다.
- 현재 프로그램에서 측정하는 빌드 시간에는 SOSD 파일을 여는 시간이 포함되지 않습니다. **과제 채점 기준에서 파일 로딩까지 빌드에 포함하는지** 확인하세요.
- 본 프로그램은 **단일 스레드**로 구현되어 있습니다.
- `README.md` 및 코드 파일을 수정했다면 팀원의 Pull Request로 검토한 후 `main`에 병합하는 것이 좋습니다.

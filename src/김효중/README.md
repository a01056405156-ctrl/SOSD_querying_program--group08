# SOSD 정수 키 검색 프로그램

## 1. 프로젝트 개요
SOSD의 **Uniform Dense (uint32)** 및 **Uniform Sparse (uint32)** 데이터셋에서 사용자가 입력한 정수 키의 위치를 찾는 C++17 콘솔 프로그램입니다. 키가 존재하지 않으면 해당 사실을 출력하고, **인덱스 빌드 시간 + 실제 검색 시간**을 밀리초(ms) 단위로 보여줍니다. 입력 및 결과 안내는 한국어로 출력합니다.

- 개발 환경: Windows 10 이상, Visual Studio 2022 이상, x64/Release
- 구현 언어: C++17
- 멀티스레딩: 사용하지 않음
- 주요 파일: `main.cpp`, `DatasetConfig.h`

## 2. 자료구조 자동 선택
| 데이터셋 | 자동 적용 방식 | 선택 근거 |
| --- | --- | --- |
| Uniform Dense (uint32) | 산술 직접 인덱싱 | 공식 Dense 값이 42부터 연속적으로 증가하여 키로 위치를 직접 계산할 수 있음 |
| Uniform Sparse (uint32) | Hybrid 탐색 | 샘플 간격 4096의 인덱스, 보간 예측, 지수 탐색 및 이진 하한 검색을 조합. 이전 Debug 실험에서 비교 방식 중 총시간이 가장 짧았음 |

Sparse의 Hybrid 방식은 **이전 실험에 근거한 기본 선택**이며 모든 컴퓨터·쿼리 조건에서 전역 최적임을 보장하지 않습니다. 최종 성능 비교는 Release/x64 환경에서 진행합니다.

## 3. 데이터셋 준비
공식 저장소: https://github.com/learnedsystems/SOSD

사용할 파일:
- `uniform_dense_200M_uint32`
- `uniform_sparse_200M_uint32`

기본 저장 위치:
```text
C:/SOSD_Data/uniform_dense_200M_uint32
C:/SOSD_Data/uniform_sparse_200M_uint32
```

각 파일은 2억 개 `uint32` 데이터를 담은 바이너리 파일(약 800,000,008바이트)이며 **GitHub에 업로드하지 않습니다**. 각 사용자 PC에서 별도로 생성하거나 준비해야 합니다.

## 4. 데이터셋 경로 연결
`DatasetConfig.h`에서 데이터셋 파일 경로를 설정합니다.

```cpp
inline constexpr const char* DENSE_PATH  = "C:/SOSD_Data/uniform_dense_200M_uint32";
inline constexpr const char* SPARSE_PATH = "C:/SOSD_Data/uniform_sparse_200M_uint32";
```

경로가 다르면 자신의 PC에 맞게 수정합니다. `main.cpp`에서 `#include "DatasetConfig.h"`를 사용하므로 두 파일을 같은 폴더에 두어야 합니다.

## 5. Visual Studio 2022 빌드 및 실행
1. Visual Studio 2022에서 C++ **콘솔 앱** 프로젝트를 엽니다(또는 새로 생성합니다).
2. `main.cpp`와 `DatasetConfig.h`를 프로젝트에 추가합니다. 헤더 파일이 `main.cpp`와 같은 디렉터리에 있는지 확인합니다.
3. 프로젝트 속성에서 C++ 언어 표준을 **ISO C++17 이상**으로 설정합니다.
4. 상단 빌드 구성을 **Release / x64**로 변경합니다.
5. 디버깅의 **명령 인수는 비워 둡니다**.
6. **빌드 → 솔루션 다시 빌드**, 이어서 **Ctrl + F5**로 실행합니다.

기존 제공 ZIP에 포함된 `SOSD_Search.sln`이 있다면 이를 더블클릭해 여는 방법도 가능합니다.

## 6. 사용 방법
프로그램 실행 후:
1. `1` 또는 `2`를 입력해 Dense/Sparse 데이터셋을 선택합니다.
2. `1. 정수 키 입력 후 위치 검색`을 선택합니다.
3. `0`부터 `4294967295` 사이의 정수 키를 입력합니다.
4. 키의 존재 여부, **0부터 시작하는 배열 인덱스**, **1부터 시작하는 위치**, 빌드 시간, 검색 시간 및 합계를 확인합니다.
5. `q`를 입력하면 키 입력을 종료합니다.

### 출력 예시 (시간은 실행 시 실측)
```text
입력한 정수 키: 100
결과: 찾았습니다!
배열 인덱스: 58
59번째 위치
인덱스 빌드 시간: ... ms
이번 키 검색 시간: ... ms
빌드 + 이번 키 검색: ... ms
```

위의 키 100 예시는 **공식 Dense 데이터셋**일 때의 위치입니다.

## 7. 성능 측정과 검증
- `인덱스 빌드 시간`: 탐색 인덱스를 구축하는 데 걸린 시간
- `이번 키 검색 시간`: 사용자가 입력한 키 **1건**을 검색하는 데 걸린 시간
- `빌드 + 이번 키 검색`: 두 시간의 합
- `빌드 + 누적 검색 시간`: 인덱스를 **한 번** 만든 뒤 여러 키를 검색한 누적 소요 시간
- `2. 자료구조 검색 속도 자동 비교`: 존재하는 키 100,000건 + 없는 키 100,000건을 대상으로 방식별 구축·검색 합계를 측정하는 메뉴

**주의:** 단일 검색 시간은 극히 짧아 측정 오차가 큽니다. 방식별 비교에는 반복 벤치마크 결과를 함께 사용하세요. 데이터 파일 열기·매핑, 쿼리 생성 및 검증 시간은 현재 빌드·검색 합계에서 제외합니다. 과제 채점자가 로딩 비용까지 포함한다면 타이머 구간 수정이 필요합니다.

## 8. 과제 제출 전 유의사항
- 512MB 메모리 제한에 대해 **완전한 준수 검증이 아직 완료되지 않았습니다.** 원본 파일은 읽기 전용 메모리 매핑으로 접근하며, Job Object의 private committed memory 제한만으로 매핑된 파일의 전체 물리 메모리 사용량이 제한된다고 볼 수 없습니다.
- 반드시 과제에서 정의한 메모리 측정 방식으로 점검해야 합니다.
- 실제 2억 건 데이터에 대한 최종 Windows Release 빌드·검색 정확성·시간 측정 결과를 남기는 것이 좋습니다.
- 소스코드와 이 README는 GitHub에 올릴 수 있지만, 데이터셋 바이너리 파일 및 개인 PC의 실행 파일·빌드 산출물은 보통 올리지 않습니다.
